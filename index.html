    The system

    A magazine's editorial process, written down for a model.

    AI drafts fast and invents facts. So I gave it editors. Watch one sentence go through the desks. Each desk has one job, and the order never changes.

    An example sentence, not a client's

    Three more desks run first when a piece starts from a topic: a reporter, an outliner and a writer.

    Four verdicts. One owner for each question.

    SHIPGoes out as it is.
    FIXGoes out after named changes.
    HOLDWaits for a decision or a source.
    KILLShould not exist.

    The system also learns my judgment. It keeps each edit I make as a before-and-after record, and it names the moves I repeat. First drafts now start nearer to the place where my edit ends.

    • 29instruction files. Each one does one kind of editorial work.
    • 1,600rows, approximately, in the claims ledger: checked claims and caught errors.
    • 28named story moves, taken from my own published writing.
    • 16synthetic MSP operators on a panel that critiques partner content.
    • 22scheduled jobs that run parts of the system without me.
    • 495before-and-after edit records kept as data.
    The test

    Then I tested it on outside material.

    To see whether the system worked beyond my own drafts, I ran the same chain of editors on published security posts from other vendors. I ran it on published vendor blogs and ruled each flag real or false by hand. I kept the score, also when the score was bad.

    Share of flags that were real, run by run

    A real flag needed a correction or tighter wording. The score fell when the fact checker became too strict. I found the cause, drafted a fix and tested it against planted errors before I applied it.
